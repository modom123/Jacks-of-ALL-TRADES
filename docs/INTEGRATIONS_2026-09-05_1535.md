# Connecting everything: Website ⇄ Zeffy ⇄ Command Center ⇄ Supabase ⇄ Vercel

## How the pieces fit (secure by design)

```
   Zeffy API (donations, contacts, campaigns — READ ONLY)
        ▲  key = server-side secret ONLY
        │
   Supabase Edge Function  zeffy-sync   ──writes──►  Supabase tables
   (holds ZEFFY_API_KEY, ANTHROPIC_API_KEY)          • zeffy_payments (admin-only)
        ▲  scheduled every 15 min (pg_cron)          • raffle_stats (public read)
        │
   ┌────┴─────────────────────────────┐
   │                                  │
 Public website (joatamp.net)     Command Center (/admin)
 reads raffle_stats (anon key)    reads all tables (admin login)
 → live "current pot", progress   → donations, finance, tasks, AI agents
```

**The golden rule:** the Zeffy key and the Supabase *service-role* key live ONLY
as server-side secrets (Supabase Edge Function env / Vercel env). The browser only
ever gets the Supabase **anon** key, which is safe because Row-Level Security keeps
donor data (`zeffy_payments.buyer_email`) admin-only. Never put the Zeffy key in
`assets/js/config.js` or any committed file.

## Step 1 — Zeffy (get the real API details)
In the Zeffy dashboard: **Settings → Organization → Integrations → API**.
1. Generate an API key (you already have one — **regenerate it after setup**, since
   the previous value was shared in chat).
2. Open Zeffy's **interactive API docs** there and note the exact:
   - **Base URL** (e.g. `https://api.zeffy.com`)
   - **Auth header** (`Authorization: Bearer <key>` or `x-api-key: <key>`)
   - **Payments** and **Campaigns** endpoint paths
   - the **campaign/form id** for the 50/50 raffle
3. If any differ from the defaults, set them as secrets in Step 2 (no code change
   needed — the function reads them from env):
   `ZEFFY_API_BASE`, `ZEFFY_AUTH_HEADER`, `ZEFFY_AUTH_SCHEME`,
   `ZEFFY_PAYMENTS_PATH`, `ZEFFY_RAFFLE_CAMPAIGN_ID`.

## Step 2 — Supabase (backend + secrets + schedule)
```bash
# link your project
supabase login
supabase link --project-ref YOUR-PROJECT-ref

# run the schema (or paste into SQL editor)
#   supabase/schema.sql               (base — if not already applied)
#   supabase/schema_zeffy_2026-09-05_1535.sql   (this integration)

# set server-side secrets (NEVER committed)
supabase secrets set ZEFFY_API_KEY=***your-regenerated-key***
supabase secrets set ZEFFY_RAFFLE_CAMPAIGN_ID=***campaign-id***
# only if Zeffy's docs differ from defaults:
# supabase secrets set ZEFFY_API_BASE=https://api.zeffy.com
# supabase secrets set ZEFFY_AUTH_HEADER=x-api-key ZEFFY_AUTH_SCHEME=

# deploy + schedule
supabase functions deploy zeffy-sync --no-verify-jwt
```
Then in the SQL editor (enables the 15-minute sync):
```sql
create extension if not exists pg_cron;
create extension if not exists pg_net;
select cron.schedule('joat-zeffy-15min','*/15 * * * *',
  $$ select net.http_post(
       url:='https://YOUR-PROJECT-ref.supabase.co/functions/v1/zeffy-sync',
       headers:='{"Content-Type":"application/json"}'::jsonb) $$);
```
Smoke test: `curl -X POST https://YOUR-PROJECT-ref.supabase.co/functions/v1/zeffy-sync`
→ expect `{ "ok": true, "synced": N, "pot_total": ... }`.

## Step 4 — Vercel (hosting the static site)
The site is static, so Vercel just serves the files; Supabase remains the backend.
1. Vercel → **Add New → Project → import** `modom123/jacks-of-all-trades`.
2. Framework preset: **Other**; Build command: none; Output dir: repo root.
   (`vercel.json` in the repo sets clean routing.)
3. Env vars: none are required in the browser build. If you later add Vercel
   *serverless* functions, set `ZEFFY_API_KEY` / `SUPABASE_SERVICE_ROLE_KEY`
   there (Project → Settings → Environment Variables) — never in the client.
4. Point the `joatamp.net` domain at Vercel. The GitHub Pages `CNAME` file has
   been **removed** (this repo now targets Vercel). Cutover order to avoid
   downtime: import the project on Vercel → add `joatamp.net` as a domain in
   Vercel → then update DNS at your registrar to the records Vercel shows
   (apex `A/ALIAS` + `www` `CNAME`). Until DNS is switched, the Vercel-generated
   `*.vercel.app` URL serves the live site.
